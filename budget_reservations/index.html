    Budget reservations and settlement

    AsyncLOCOScheduler reserves a priced task's estimated cost before returning an acquisition. In reject mode, admission requires:

    settled spend + outstanding reservations + new estimate <= per-agent limit

acquire slot -> reserve policies -> return handle -> execute -> settle -> free slot
                      |
                later check/hook fails -> cancel reservations -> free slot

    Check-and-reserve and settlement use the same process-local lock on BudgetPolicy. Sharing one policy object across schedulers coordinates their commitments. Separate policy objects, separate processes, and separate hosts do not share a ledger. This is not a distributed transaction, persistent ledger, or provider billing cap.

    Existing callers

    Existing async with scheduler.acquire(agent_id): and release_handle(handle) usage continues to work. Settlement defaults to the original reserved estimate, even if task weight changes during execution. spent() remains settled spend; reserved() reports outstanding commitments; remaining() subtracts both. summary() adds a reserved field. Scheduler metrics still attribute estimated task weights; budget.spent() is the settled budget ledger, not token telemetry.

    Direct callers own task submission and dequeueing. Pass task=task to bind an acquisition to the exact submitted task, then remove that task by identity. Without task=, acquisition claims the next unclaimed queued task in submission order. Its price is reserved at admission. Convenience wrappers and the callback adapters handle their own task cleanup; see Task lifecycle.

    Reconcile a known charge

    Charges must use the same units as the budget and task estimate. SDK token counts are not automatically converted to currency or normalized task weights.

    from loco import AsyncLOCOScheduler, BudgetManager, SharedResource, Task

budget = BudgetManager(default_limit=10)
scheduler = AsyncLOCOScheduler([], SharedResource("provider", capacity=4), budget=budget)
task = Task(weight=5)
await scheduler.submit_task("research", task)

async with scheduler.acquire("research", task=task) as handle:
    try:
        result = await call_provider()  # application's provider function
        handle.set_actual_cost(result.verified_charge_in_budget_units)
    finally:
        scheduler.get_agent("research").remove_task(task, completed=True)

    For split callbacks, release in a finally block:

    task = Task(weight=5)
await scheduler.submit_task("research", task)
handle = await scheduler.acquire_start("research", task=task)
actual_cost = None
try:
    result = await call_provider()
    actual_cost = result.verified_charge_in_budget_units
finally:
    scheduler.get_agent("research").remove_task(task, completed=True)
    await scheduler.release_handle(handle, actual_cost=actual_cost)

    Known zero cost is accepted. Invalid negative, non-finite, boolean, or nonnumeric charges are rejected before consuming an explicit release handle; correct the value and release it. A validated charge can also be set on the context handle before exit. Releasing twice never charges twice. Handles cannot be released by another scheduler.

    An actual charge above its reservation is recorded in full. It may exceed the limit; later admissions see that settled charge and are rejected. No controller can retroactively prevent a charge already incurred. A strict real-money ceiling requires safe upper-bound estimates, bounded provider calls, and billing in consistent units. Accurate settlement improves future decisions; it does not turn an underestimate into a guarantee.

    Failure and cancellation

    • A policy rejection or admission-hook failure cancels prior reservations and frees the slot. Rejected tasks remain in the caller's queue until removed.
    • Cancelling or timing out before admission does not create a budget reservation.
    • Once admitted, failure or cancellation settles the original estimate unless a verified actual charge was supplied. This removes the reservation without silently refunding potentially billable work. Use zero only when known unbilled.
    • Completion-policy and lifecycle-hook errors cannot skip settlement of other policies or leave the resource held. Resource cleanup completes under cancellation.
    • Policies are snapshotted at admission; removing one while a call runs does not discard its settlement obligation. Existing stateless policy check/record hooks continue through the new reserve/settle/cancel lifecycle defaults.
    • reset() / reset_all() reject resets while affected reservations exist, including zero-cost reservations. Lowering a limit does not revoke work already admitted.

    Direct budget users can call reserve(agent_id, cost), settle(token, actual_cost), and cancel(token); settlement and cancellation are idempotent. check() remains an advisory read, not an atomic authorization. Direct record_spend() records an external charge; it does not replace reservation-based admission.

    alert and downgrade modes remain intentionally permissive. Empty task queues still take the legacy taskless acquisition path and are not priced or budgeted. Calls outside LOCO remain outside enforcement. Tenant accounting uses a separate admission ledger described in Resource lifecycle. Neither ledger provides distributed enforcement.

    Policy decisions and shutdown

    Policy.check() returns True for permission, False for denial, or raises PolicyViolationError with a reason. A non-boolean return raises TypeError. Warnings must be recorded separately and return True. Budget alert and downgrade modes follow this rule; inspect alerts to detect an overage. Custom reservation overrides must enforce this contract themselves.

    Shutdown rejects new acquisitions and cancels every queued waiter, including multiple callers for the same agent. A cancellation wakeup never grants a resource slot. Waiting callers receive asyncio.CancelledError; the shutdown report counts waiting calls, not distinct agent IDs. Existing holders may finish and settle their commitments. A shutdown timeout does not terminate those actions.
